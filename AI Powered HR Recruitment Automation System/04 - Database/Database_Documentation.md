# Database Documentation

## 1. Database Overview

The AI-Powered HR Recruitment Automation System uses Google Sheets as its centralized recruitment database.

The database is named `AI-HR-Recruitment-Database` and contains four worksheets that organize job requirements, candidate applications, notification records, and interview information.

## 2. Database Structure

### 2.1 Jobs

**Purpose:** Stores job descriptions and the requirements extracted by WF-03 for candidate matching.

| Field | Description |
|---|---|
| Job ID | Unique job identifier used to associate applications with a job |
| Required Skills | Mandatory skills extracted from the job description |
| Preferred Skills | Desirable skills extracted from the job description |
| Experience Required | Required experience criteria |
| Education Required | Required education criteria |
| Job Description | Additional job description context |
| Job Status | Indicates job availability |

WF-03 populates the extracted job requirements in this worksheet.

### 2.2 Applications

**Purpose:** Stores candidate application information, extracted resume details, AI-assisted matching results, and recruitment decisions.

| Field | Description |
|---|---|
| Application ID | Unique application identifier |
| Candidate Name | Candidate's name |
| Email | Candidate email address |
| Phone | Candidate contact number |
| Job ID | Identifier of the applied job |
| Resume Link | Link to the stored resume |
| Applied Date | Application submission date and time |
| Parsed Skills | Skills extracted from the resume |
| Education | Extracted education information |
| Experience | Extracted experience information |
| AI Match Score | AI-generated candidate matching score |
| Matching Explanation | Explanation of the matching result |
| Candidate Category | Assigned candidate category |
| Application Status | Current application status |
| HR Decision | HR recruitment decision |
| Consent Status | Candidate consent status |

### 2.3 Notification Logs

**Purpose:** Maintains records of automated notifications generated by the recruitment workflows.

| Field | Description |
|---|---|
| Notification ID | Unique notification identifier |
| Application ID | Related application identifier |
| Notification Type | Type of notification |
| Recipient Email | Notification recipient |
| Sent Status | Notification delivery status |
| Sent At | Notification timestamp |
| Workflow Name | Workflow responsible for the notification |
| Error Details | Error information, if applicable |

### 2.4 Interviews

**Purpose:** Stores interview scheduling and tracking information.

| Field | Description |
|---|---|
| Interview ID | Unique interview identifier |
| Application ID | Related application identifier |
| Candidate Name | Candidate's name |
| Candidate Email | Candidate email address |
| Job Title | Associated job title |
| Interview Date | Scheduled interview date |
| Interview Time | Scheduled interview time |
| Interview Mode | Interview format |
| Meeting Link | Interview meeting link |
| Interview Status | Current interview status |
| HR Notes | Notes recorded by HR |

## 3. Database Relationships

The database uses identifiers to associate related records:

- `Jobs.Job ID` matches `Applications.Job ID`.
- `Applications.Application ID` is referenced by Notification Logs through `Application ID`.
- `Applications.Application ID` is referenced by Interviews through `Application ID`.

These relationships help maintain consistency across job requirements, candidate applications, notifications, and interviews.

## 4. Data Management

- Google Sheets acts as the centralized recruitment database.
- n8n workflows automate the creation and updating of relevant records.
- Separate worksheets organize job, application, notification, and interview information.
- Database access should be restricted to authorized users.

## 5. Data Privacy and Security

- Candidate information should only be accessible to authorized personnel.
- Resume links and contact information should not be exposed in public reports.
- Credentials and private candidate records must not be included in the public project repository.
- AI-generated matching results should support HR review rather than replace human decisions.
